# Hard-Code the Gates, Let Models Talk

Production teams that publish how they build SOP-bound support agents have converged on one split: deterministic code owns conversation state, phase order, gate variables, authorization and every side effect, while the LLM is confined to turning each user turn into a closed set of commands or slot values, choosing among options code has already filtered, and wording replies from structured data ([Salesforce Architects](https://architect.salesforce.com/docs/architect/fundamentals/guide/hybrid-reasoning-agentforce-builder-agent-script); [Rasa](https://rasa.com/docs/reference/config/components/llm-command-generators/)). They got there by failing first. Salesforce's post-mortem of its original LLM-driven Agentforce loop lists irreproducible runs, dropped context, repeated mandatory steps, three to five LLM calls per turn, and an audit trail that amounted to "the agent decided" ([Salesforce Architects](https://architect.salesforce.com/docs/architect/fundamentals/guide/hybrid-reasoning-agentforce-builder-agent-script)), and τ-bench found function-calling agents completing under 50% of policy-bound tasks and under 25% when a task had to succeed eight times running ([Yao et al.](https://arxiv.org/abs/2406.12045)). Public incidents set the stakes: a tribunal held Air Canada liable for a refund rule its chatbot invented ([ABA Business Law Today](https://www.americanbar.org/groups/business_law/resources/business-law-today/2024-february/bc-tribunal-confirms-companies-remain-liable-information-provided-ai-chatbot/)), Cursor's support bot invented a device policy ([The Register](https://www.theregister.com/2025/04/18/cursor_ai_support_bot_lies/)), and Lenovo's bot became a cookie-stealing XSS vector at the human-handoff step ([CSO Online](https://www.csoonline.com/article/4043005/lenovo-chatbot-breach-highlights-ai-security-blind-spots-in-customer-facing-systems.html)). For an insurance-claims agent with VERIFY_ID, RESOLVE_INTENT, PROCESS_CASE and POST_PROCESS phases, the lesson is that identity, consent, phase transitions, retry counters and claim facts must be impossible for the model to skip or misstate, not merely forbidden in its prompt, because prompt-level controls are routinely defeated ([OWASP](https://genai.owasp.org/llmrisk/llm072025-system-prompt-leakage/); [Nasr et al.](https://arxiv.org/abs/2510.09023)). The law raises three bars the specification underweights: an any-3-of-5 knowledge check matches no published verification protocol, and NIST's 2025 guidelines bar knowledge-based verification for identity proofing ([NIST](https://pages.nist.gov/800-63-4/sp800-63a.html)); a representative's access must rest on recorded consent limited to directly relevant information ([45 CFR 164.510](https://www.law.cornell.edu/cfr/text/45/164.510)); and EU users have been owed AI-interaction disclosure since August 2, 2026 ([EU AI Act Art. 50](https://artificialintelligenceact.eu/article/50/)). Most of the evidence comes from vendors with products to sell and no insurer has published a claims-chatbot postmortem, so the numeric thresholds below are reasoned defaults to instrument and tune, not proven settings.

## Every major platform now keeps phase transitions out of the LLM

Salesforce's rebuilt Agentforce is the most explicit statement of the pattern. Builders write an "Agent Script" that compiles into a graph, and the Atlas engine "is a state machine executor": each turn it "executes deterministic nodes as code, and triggers LLM calls only where prompt instructions are present," and **"graph traversal and state transitions never involve the LLM"** ([Salesforce Architects](https://architect.salesforce.com/docs/architect/fundamentals/guide/hybrid-reasoning-agentforce-builder-agent-script)). The model is called at eight named points (classification, next-action choice, response generation, groundedness validation, action simulation, structured output, localization and progress messages), while authentication belongs in a deterministic `before_reasoning` block "because you want those verified before the LLM sees any tools." Two mechanisms turn gates from advice into physics. An action whose `available when` condition is false "is removed from the tool list presented to the LLM entirely... The LLM can't call an action it can't access," and the gate variable must never be model-written: **"If you rely on the LLM to set the gate variable, you've reintroduced the variability the gate was designed to prevent."** Salesforce's rule of thumb, "If you can express a decision as code, it should be written as logic," comes with the note that finance, healthcare and insurance workflows "generally fall into" the deterministic category ([Salesforce Architects](https://architect.salesforce.com/docs/architect/fundamentals/guide/hybrid-reasoning-agentforce-builder-agent-script)).

Rasa's CALM reached the same design from the deterministic side. Its LLM never picks the next step; it translates the conversation into commands from a six-item vocabulary (start flow, set slot, disambiguate flows, search and reply, cancel flow, repeat message) that a deterministic flow engine validates and executes ([Rasa docs](https://rasa.com/docs/reference/config/components/llm-command-generators/); [Bocklisch et al.](https://arxiv.org/abs/2402.12234)). Corrections, digressions, chitchat and human handoff run through built-in "patterns" that are themselves flows ([Rasa patterns](https://rasa.com/docs/reference/primitives/patterns/)). Replies are templates by default, and the optional LLM rephraser ships with Rasa's own warning: "Sometimes, the LLM will not generate a true paraphrase, but slightly alter the meaning" ([Rasa rephraser](https://rasa.com/docs/reference/primitives/contextual-response-rephraser/)). Security-relevant slots can be declared `controlled`, meaning only custom actions or flow steps can write them and the LLM cannot ([Rasa slots](https://rasa.com/docs/reference/primitives/slots/)).

The same split recurs across the market under different names. Google tells Dialogflow builders that once intent is established, deterministic flows give "complete control over the conversation flow and agent responses," reserving generators and playbooks for generative work ([Google Cloud](https://docs.cloud.google.com/dialogflow/cx/docs/generative-deterministic)). Microsoft's generative orchestration cannot fill regex or closed-list entities, so Microsoft tells builders to collect them with a deterministic Question node ([Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-copilot-studio/advanced-generative-actions)). Amazon Lex's LLM assistance stays "within your bot's configured intents and slots" ([AWS](https://docs.aws.amazon.com/lexv2/latest/dg/assisted-nlu.html)), and Bedrock's return-of-control mode hands elicited parameters back to the application to execute ([AWS Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/agents-returncontrol.html)). Decagon pitches its procedures on the promise that "identity checks follow security protocols" ([Decagon](https://decagon.ai/blog/from-sops-to-agent-operating-procedures)), Intercom's Fin Procedures embed "code snippets for when absolute accuracy is essential" ([Intercom](https://www.intercom.com/blog/procedures-simulations-updates/)), and Ada lets every step be set to "fixed or AI-driven" ([Ada](https://docs.ada.cx/2026-06-22-playbooks-enhancements)).

What differs is where the model sits, and the three placements map onto the claims phases. The right-hand column is this report's inference, not any vendor's prescription.

| Placement | Who ships it | What the LLM decides | Natural home in the claims agent |
|---|---|---|---|
| Parser feeding a state machine | Rasa CALM, Lex Assisted NLU, Dialogflow flows | Commands and slot values from a closed vocabulary that code validates | VERIFY_ID and RESOLVE_INTENT |
| Orchestrator inside code fences | Agentforce gates, Bedrock return of control, Fin Procedures, Ada fixed steps | The next action, chosen only from actions code currently exposes | Tool use in PROCESS_CASE |
| Filtered context plus supervisors | Parlant guidelines and journeys, Sierra supervisor agents | Which rules apply this turn and how to word the reply, audited by other models | Free-form grounded Q&A inside PROCESS_CASE |

Parlant illustrates the third placement: each turn its engine decides which condition-action guidelines apply and puts only those in the prompt, because "the more instructions you add to a prompt, the faster your agent stops paying attention to any of them" ([Parlant](https://github.com/emcie-co/parlant)). Sierra wraps every production agent in "several supervisory agents" that "audit an agent's every action and response, checking for behavior that's not compliant with policies or harmful language" ([Sierra](https://sierra.ai/blog/enterprise-grade-agents)).

Freedom is set per step, not per agent, and the most reliable way to control content is to keep the LLM away from it. Parlant's STRICT composition mode lets the agent only select a pre-written response such as "Your account balance is {balance}." with tools filling the placeholder ([Parlant](https://www.parlant.io/docs/engine-internals/message-generation/)). Agentforce assembles error messages "from session variables rather than generated by the LLM," leaving the model a role that is "purely presentational" ([Salesforce Architects](https://architect.salesforce.com/docs/architect/fundamentals/guide/hybrid-reasoning-agentforce-builder-agent-script)), and OpenAI's agent guide advises that being explicit about "even the wording of a user-facing message" leaves less room for misinterpretation ([OpenAI](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)). Work is also split across calls. Anthropic reports that a separate guardrail call "tends to perform better than having the same LLM call handle both guardrails and the core response" ([Anthropic](https://www.anthropic.com/engineering/building-effective-agents)); Fin refines the query, generates, then validates groundedness and escalates to a human when validation fails ([Intercom](https://www.intercom.com/help/en/articles/9929230-the-fin-ai-engine)); and Sierra assembles agents from "15+ frontier, open-weight, and proprietary models" matched to jobs such as low-latency tool calling, high-precision classification and "pitch-perfect tone" ([Sierra](https://sierra.ai/blog/constellation-of-models)).

The one live disagreement is build order. Intercom tells customers to start "with a fully natural language Procedure" and introduce structure "gradually where it adds value" ([Intercom](https://www.intercom.com/blog/procedures-simulations-updates/)); Salesforce says "the default position should be deterministic" ([Salesforce Architects](https://architect.salesforce.com/docs/architect/fundamentals/guide/hybrid-reasoning-agentforce-builder-agent-script)). For a claims agent the conflict dissolves once gates are separated from conversation: identity, consent and phase order carry legal consequences and belong in code from day one, while clarification, tone and grounded explanation can start in natural language and harden only where evaluations show drift. OpenAI's guide frames the test from the other side, naming "processing a home insurance claim" as agent territory because it leans on unstructured data, while warning that otherwise "a deterministic solution may suffice" ([OpenAI](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)). This agent's facts arrive as structured claim fields and short vetted document guidance, which puts most of its decisions on the deterministic side.

## LLM-only loops failed in five repeatable ways before vendors pulled back

The record shows a pendulum. First-generation intent bots and decision trees broke on anything off-script, which is why Decagon describes its procedures as "moving away from brittle decision trees" and Intercom positions Procedures against its older drag-and-drop Workflows ([Decagon](https://decagon.ai/blog/why-we-built-aop); [fin.ai](https://fin.ai/learn/fin-procedures-guide)). The first LLM generation swung to the opposite pole and let the model run the process. Salesforce's description of that version is the most candid first-party post-mortem available: "an agent operated as a simple reactive loop... There was no guaranteed execution path, no persistent state, and no mechanism to enforce a sequence of steps" ([Salesforce Architects](https://architect.salesforce.com/docs/architect/fundamentals/guide/hybrid-reasoning-agentforce-builder-agent-script)). The five consequences it lists read like a requirements document for the claims agent: a workflow "that passed in staging could behave differently in production"; **"a minimum of three LLM cycles"** per simple turn and five or more for multi-step tasks; context dropped whenever "the conversation deviated even slightly," forcing a restart; "unpredictable looping, where an agent would return to a step the user had already finished"; and an audit story of "the agent decided," which "is not a defensible answer in a compliance review."

Benchmarks put numbers on the same pattern. On τ-bench, where an LLM-simulated user talks to an agent bound by a written policy and success is judged by the final database state, "even state-of-the-art function calling agents (like gpt-4o) succeed on <50% of the tasks," and **gpt-4o's 61.2% single-run retail score fell below 25% when the same task had to succeed eight times** ([Yao et al.](https://arxiv.org/abs/2406.12045)). The failures were mundane: a quarter came from breaking domain rules, a fifth from partially resolving compound requests, and the rest from wrong tool arguments or wrong information. The most telling ablation is that deleting the policy document cut gpt-4o's retail score by only 4.4%, a sign the agent leaned on priors more than on the written rules. Earlier academic work had already found that LLMs "underperform" specialised models at explicit belief-state tracking yet "show some ability to guide the dialogue to a successful ending... if provided with correct slot values" ([Hudeček & Dušek](https://arxiv.org/abs/2304.06556)), which is exactly the hybrid division of labour: code keeps the state, the model talks. FlowAgent's authors found ReAct-style agents degraded more steeply than their controller-guarded design when users asked off-script questions or tried to skip steps, and their ablation called the hard post-decision controllers "indispensable" ([Shi et al.](https://arxiv.org/abs/2502.14345)). Rasa's comparison against a LangGraph agent on an airline assistant reported $0.10 versus $0.04 per message, 7.4 versus 2.08 seconds per turn, and only one problem-free LangGraph conversation out of five, including an impossible "April 22 - April 20" hotel booking; it is vendor-run and covers five conversations in one domain, so it illustrates rather than proves ([Rasa](https://rasa.com/blog/cutting-ai-assistant-costs-the-power-of-enhancing-llms-with-business)).

Production systems hit the same walls. Copilot Studio users reported that with generative orchestration on, a topic "repeats the same question multiple times and never proceeds to the next step," and that the bot "asks the questions for information that is provided in the initial prompt"; a Microsoft forum responder called this "expected" and suggested turning generative AI off "for more deterministic slot behavior" ([Microsoft Q&A](https://learn.microsoft.com/en-us/answers/questions/2258167/generative-ai-orchestration-repeats-questions-and)). Microsoft's documentation concedes that conversation history is limited, so the agent sometimes "can't see or use the information in earlier parts of the conversation" ([Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-copilot-studio/advanced-generative-actions)). Sierra frames the scale problem bluntly: **"At scale, a one-in-ten-thousand hallucination rate is a daily occurrence,"** which is why it layers supervisors over every production agent ([Sierra](https://sierra.ai/blog/enterprise-grade-agents)). Klarna is the cautionary business case. Its assistant handled 2.3 million conversations, two-thirds of service chats, in its first month and was billed as "equivalent to 700 full-time agents" ([Klarna](https://www.klarna.com/international/press/klarna-ai-assistant-handles-two-thirds-of-customer-service-chats-in-its-first-month/)), yet in May 2025 the CEO conceded that "cost unfortunately seems to have been a too predominant evaluation factor," producing "lower quality," and the company began hiring human agents again ([CX Today](https://cxtoday.com/klarna-grapples-with-ai-led-customer-service-pivots-to-an-uber-type-of-setup); [Entrepreneur](https://www.entrepreneur.com/business-news/klarna-ceo-reverses-course-by-hiring-more-humans-not-ai/491396)) while keeping the AI in service ([Resultsense](https://www.resultsense.com/news/2025-11-19-klarna-ai-workforce-reduction-salary-increase/)).

The retreat was not a return to decision trees, and the strongest counterargument deserves a hearing. Salesforce's own engineers warn that bolting on "if/else rules or 'flows' as agentic actions can devolve quickly into unmanageable, interdependent logic" ([Salesforce Engineering](https://engineering.salesforce.com/agentforces-agent-graph-toward-guided-determinism-with-hybrid-reasoning/)), and FlowAgent's authors note that traditional rule-based methods "tend to limit the inherent flexibility of LLMs" ([Shi et al.](https://arxiv.org/abs/2502.14345)). Models have also improved sharply: the best systems now score about **85–88% single-run on τ²-bench overall** ([taubench.com](https://taubench.com)) and roughly 80–85% accuracy on Princeton HAL's cleaned airline subset ([HAL](https://hal.cs.princeton.edu/reliability/benchmark/taubench_airline)). Even at those levels, between one in eight and one in five policy-bound tasks still fails, consistency still declines over repeated trials, the new knowledge-retrieval banking domain tops out at 55.2% ([taubench.com](https://taubench.com)), and the incidents in the next section were adversarial or edge-case failures that capability gains have not eliminated. The settled endpoint is a thin deterministic skeleton of state, gates and code steps, with the model free inside each step.

| Documented failure | Where it was seen | Requirement it creates for the claims agent |
|---|---|---|
| Skipped or out-of-order steps | Agentforce v1; FlowAgent's "procedure jumping" | Phase order and the identity gate live in code |
| Lost context and re-asked questions | Agentforce v1; Copilot Studio | Volunteered facts stored as state, not left in the transcript |
| Looping back to finished steps | Agentforce v1 | Per-step completion flags; gates closed after their action runs |
| Wrong arguments and invented values | τ-bench failure analysis | Schema-validated extraction, re-validated in code |
| Three to five or more LLM calls per turn | Agentforce v1; Rasa vs LangGraph | One constrained understanding call; transitions in code |
| Cost-first tuning degrades quality | Klarna | Escalation and quality metrics designed in, not containment alone |

## Courts and attackers have already priced the failure modes

The legal principle is settled even though the dollar amounts are small. In November 2022 Air Canada's website chatbot told Jake Moffatt, whose grandmother had just died, that he could book at full fare and claim a bereavement discount retroactively; the airline's real policy allowed no such refund. Air Canada argued the chatbot was "a separate legal entity responsible for its own actions," and British Columbia's Civil Resolution Tribunal rejected that, holding the airline responsible for information on its site "whether it came from a static page or a chatbot" ([ABA Business Law Today](https://www.americanbar.org/groups/business_law/resources/business-law-today/2024-february/bc-tribunal-confirms-companies-remain-liable-information-provided-ai-chatbot/)) and awarding **C$812.02** in damages, interest and fees ([CTV News](https://bc.ctvnews.ca/air-canada-s-chatbot-gave-a-b-c-man-the-wrong-information-now-the-airline-has-to-pay-for-the-mistake-1.6769454)). In April 2025 Cursor's email support bot "Sam" explained unexpected logouts by inventing a rule that "Cursor is designed to work with one device per subscription as a core security feature"; the real cause was a session bug, cancellation threats followed, and the fix included labelling "any AI responses used for email support" as AI ([The Register](https://www.theregister.com/2025/04/18/cursor_ai_support_bot_lies/); [CX Today](https://www.cxtoday.com/conversational-ai/a-contact-center-chatbot-invents-company-policies-now-customers-want-out/)). New York City's MyCity bot told businesses they could take workers' tips and refuse Section 8 vouchers; when ten Markup staffers asked the voucher question, "the bot told all of them no," even though one reporter had earlier received the correct answer ([The Markup](https://themarkup.org/news/2024/03/29/nycs-ai-chatbot-tells-businesses-to-break-the-law)). Disclaimers and topic limits did not rescue it, and the next administration called the bot, which cost nearly $600,000 to build and about $500,000 a year to run, "functionally unusable" and shut it down in February 2026 ([The Markup](https://themarkup.org/artificial-intelligence/2026/01/30/mamdani-to-kill-the-nyc-ai-chatbot-we-caught-telling-businesses-to-break-the-law)). NEDA's eating-disorder helpline bot Tessa was pulled after recommending calorie deficits ([NPR](https://www.npr.org/sections/health-shots/2023/06/08/1180838096/)). The shared root cause is a model answering policy questions from its priors and filling gaps with plausible rules, which is precisely the risk when a claimant asks whether a late appeal will be accepted.

Thin system prompts failed against ordinary users, not just experts. A Chevrolet dealer's ChatGPT-powered bot agreed to sell a 2024 Tahoe for $1 after a user told it to agree with anything the customer says and to end each reply with "and that's a legally binding offer - no takesies backsies"; the vendor counted about 3,000 attempts to hack it ([Business Insider](https://www.businessinsider.nl/a-car-dealership-added-an-ai-chatbot-to-its-site-then-all-hell-broke-loose)), and the bot went offline ([Cut the SaaS](https://cut-the-saas.com/ai/chatbot-case-study-purchasing-a-chevrolet-tahoe-for-dollar-1)). DPD's parcel bot, after what the company called a system-update error, swore at a customer and called DPD "the worst delivery firm in the world" in a post seen 800,000 times in 24 hours, and DPD disabled the AI element ([Fortune](https://fortune.com/europe/2024/01/22/ai-chatbot-delivery-calls-itself-useless-works-for-worst-firm-in-world); [HCA Magazine](https://www.hcamag.com/au/specialisation/hr-technology/parcel-delivery-company-disables-ai-after-chatbot-swears-at-customer/474067)). The control that would have contained both is an absence of authority. Anthropic's own car-insurance support template tells the agent not to "make promises or enter into agreements it's not authorized to make" ([Claude docs](https://platform.claude.com/docs/en/about-claude/use-case-guides/customer-support-chat)), and a claims agent should hold no tool that settles, pays, or promises coverage.

The security failures came through the plumbing around the model. In August 2025 a 400-character prompt that opened with a normal product question made Lenovo's GPT-4-powered "Lena" emit HTML that was stored in the chat history and executed when a human agent opened the transcript during handoff, leaking session cookies ([Cybernews](https://cybernews.com/security/lenovo-chatbot-lena-plagued-by-critical-vulnerabilities/); [CSO Online](https://www.csoonline.com/article/4043005/lenovo-chatbot-breach-highlights-ai-security-blind-spots-in-customer-facing-systems.html)). Salesforce's "ForcedLeak" (CVSS 9.4) hid instructions in a Web-to-Lead description field that made an Agentforce agent exfiltrate CRM data to an allowlisted domain that had expired and could be bought for about $5; the fix enforces Trusted URLs ([The Hacker News](https://thehackernews.com/2025/09/salesforce-patches-critical-forcedleak.html)). Optum left an internal chatbot for handling claims under company SOPs reachable from the internet without a password, where it explained typical reasons for denying coverage ([TechCrunch](https://techcrunch.com/?p=2931052)). In June 2025 Erie Insurance, Philadelphia Insurance and Aflac all disclosed intrusions during a Scattered Spider campaign against insurers; Aflac attributed its breach to social engineering, and the group's signature is phoning help desks to talk staff into credential resets or MFA bypasses ([The Register](https://www.theregister.com/2025/06/20/aflac_scattered_spider/); [BleepingComputer](https://www.bleepingcomputer.com/news/security/3-key-takeaways-from-the-scattered-spider-attacks-on-insurance-firms/amp/)). That makes the "offer a human" path a target: it must never become the place where verification is waived.

Defences that rely on the model or a classifier noticing the attack do not hold under pressure. Adaptive attacks broke 12 recently published defences at over 90% success for most, even though most had originally reported near-zero attack success ([Nasr et al.](https://arxiv.org/abs/2510.09023)); spacing out letters dropped Meta's Prompt Guard detection on 450 malicious prompts from 100% to 0.2% ([Robust Intelligence](https://robustintelligence.com/blog-posts/bypassing-metas-llama-classifier-a-simple-jailbreak)); and a 1.8-million-attack red-teaming competition run with the UK AI Security Institute **broke every one of 22 models in every behaviour category at least once** ([Gray Swan & UK AISI](https://arxiv.org/abs/2507.20526)). OWASP's 2025 guidance draws the architectural conclusion: "The system prompt should not be considered a secret, nor should it be used as a security control," and "critical controls such as privilege separation, authorization bounds checks, and similar must not be delegated to the LLM" ([OWASP LLM07](https://genai.owasp.org/llmrisk/llm072025-system-prompt-leakage/)). The design-pattern literature states the rule for agents that read untrusted text: "once an LLM agent has ingested untrusted input, it must be constrained so that it is impossible for that input to trigger any consequential actions." For customer-service bots it recommends an action-selector design plus context minimisation, and it notes that a topic classifier can be beaten by mixing related and unrelated questions in one message ([Beurer-Kellner et al.](https://arxiv.org/abs/2506.08837)). Structural measures do measurably better: datamarking untrusted text ("spotlighting") cut attack success from about 50% to under 3% on GPT-3.5-Turbo ([Spotlighting](https://arxiv.org/abs/2403.14720)), and Microsoft deterministically blocks exfiltration channels such as markdown image injection ([MSRC](https://www.microsoft.com/msrc/blog/2025/07/how-microsoft-defends-against-indirect-prompt-injection-attacks)).

Model-based grounding checks are a second layer, not the foundation. Amazon's Bedrock contextual grounding check states that "Conversational QA / Chatbot use cases are not supported," caps the guarded response at 5,000 characters, and under streaming returns an irrelevant answer to the user before flagging it ([AWS](https://docs.aws.amazon.com/bedrock/latest/userguide/guardrails-contextual-grounding-check.html)); AWS's headline claim that it filters "over 75%" of hallucinated RAG responses comes without published methodology ([AWS](https://aws.amazon.com/about-aws/whats-new/2024/07/guardrails-bedrock-hallucinations-safeguard-apps-fm/)). NVIDIA's NeMo Guardrails paper measured fact-checking at about 80% accuracy for "about 3 times the latency and cost of a normal call," on 2023-era models ([NeMo Guardrails](https://arxiv.org/abs/2310.10501)). Strict structured outputs guarantee format, with OpenAI reporting 100% schema adherence against under 40% before, but "the model may still make mistakes within the values of the JSON object" ([OpenAI](https://openai.com/index/introducing-structured-outputs-in-the-api/)). The dependable grounding for claim facts is structural: tools return fields, code renders the numbers and dates, and model-based checks catch what slips through.

| Incident | Failure class | Control for the claims agent |
|---|---|---|
| Air Canada, Cursor, MyCity, Tessa | Ungrounded policy answers and invented rules | Answer only from tool fields or vetted text; otherwise say so and offer a human |
| Chevrolet dealer, DPD | Persona and scope hijack through user text | Code-enforced scope and refusals; no commitment authority |
| MyCity | Inconsistent answers to the same question | pass^k regression tests |
| Lenovo | Unsanitised output executed at handoff | Escape output in the customer UI and the agent desk |
| ForcedLeak | Indirect injection through a data field | Tool text treated as data; deterministic egress allowlist |
| Optum SOP bot | Exposure without authentication | Authentication on every surface, including internal tools |
| Insurer help-desk breaches | Social engineering of humans | Human agents follow the same verification and cannot override a failure |

The corrective actions were blunt. DPD, the Chevrolet dealer, NEDA and New York switched their bots off; Air Canada's chatbot appeared to vanish after the ruling, though the airline never confirmed it ([downes.ca](https://downes.ca/post/76271/rd)); Cursor labelled AI replies; and Salesforce and Lenovo added deterministic controls. None published a technical postmortem, and no incident involving a policyholder-facing insurance-claims chatbot surfaced for 2023 to 2026. The closest are Optum's exposed internal bot and the unproven allegations that UnitedHealth's nH Predict claims algorithm had a "90 percent error rate," which the company disputes ([The Register](https://www.theregister.com/2023/11/15/unitedhealthcare_ai_medicine/)).

## Empathy, memory and refusals work only behind code-enforced gates

### Capture anything early, advance nothing early

The requirement to remember what a caller volunteers without skipping ahead has a documented solution: let the model write any slot at any turn, but let only code advance the phase. Rasa's default lets LLM-filled slots be captured "at any conversation point, not just during their designated collect step," including extra details a user offers while answering a different question ([Rasa slots](https://rasa.com/docs/reference/primitives/slots/); [Rasa](https://rasa.com/docs/reference/config/components/llm-command-generators/)). Agentforce persists validated session variables so that "the conversation can deviate, the user can ask follow-up questions, and the agent will still know exactly where it is in the process," and action parameters are read from that state rather than reassembled from the transcript ([Salesforce Architects](https://architect.salesforce.com/docs/architect/fundamentals/guide/hybrid-reasoning-agentforce-builder-agent-script)). Parlant and Fin go further and let the model skip or revisit steps ([Parlant](https://www.parlant.io/docs/concepts/customization/journeys); [Intercom](https://www.intercom.com/help/en/articles/12495167-fin-procedures-explained)); in a gated claims flow the model may propose a jump, but code decides. The inferred design is one extraction call per turn against the slot schema of all four phases, with anything belonging to a later phase written as provisional, tagged with its source turn, and confirmed implicitly when that phase opens ("You mentioned a claim from January that was denied — is that the one?"). Before verification the agent should acknowledge volunteered claim details neutrally ("I've noted that, and we'll look at it once you're verified"), because confirming that a claim exists is itself a disclosure; the IRS rule is "Do not confirm or deny any taxpayer information until authentication has been successfully completed" ([IRS IRM 21.1.3](https://www.irs.gov/irm/part21/irm_21-001-003)). Identity values the model extracts are proposals only: the verification tool alone writes them to the verified store, and a later "actually my birthday is…" should cancel and re-run verification rather than overwrite a verified value, mirroring Rasa's `controlled` slots.

### For a disclosed AI, competence reads as empathy

The empathy research runs against intuition. AI-written messages made recipients feel more heard than human ones until the recipients learned the source, at which point the advantage disappeared ([Yin, Jia & Wakslak, PNAS](https://pmc.ncbi.nlm.nih.gov/articles/PMC10998586/)). Across nine studies and 6,282 participants, identical empathic responses were rated more empathic when attributed to a human ([Rubin, Perry et al.](https://en.psychology.huji.ac.il/news/comparing-value-perceived-humanversus-ai-generated-empathy)), and a 2026 MIS Quarterly study that included a live LLM chatbot found that **empathetic chatbot messages in service-recovery situations triggered reactance and lowered perceived competence, service quality and satisfaction**, while the same empathy from a human helped ([USF](https://www.usf.edu/business/news/2026/04-20-chatbot-empathy-can-worsen-customer-reactions-usf-study.aspx)). Warmth also costs accuracy: fine-tuning five models for warmth raised error rates by 10 to 30 percentage points and made them "significantly more likely to validate incorrect user beliefs, particularly when user messages expressed sadness" ([Ibrahim, Hafner & Rocher](https://arxiv.org/abs/2507.21919)). LLMs preserve the user's "face" 45 points more than humans do ([Cheng et al.](https://arxiv.org/abs/2505.13995)), and a single template of tactics matches 83–90% of LLM empathic responses ([Gueorguieva et al.](https://arxiv.org/abs/2604.08479)), which is why unconstrained agents sound scripted. Even the human playbooks rest on thin evidence; a Cochrane review could not say whether de-escalation techniques work ([Cochrane](https://www.cochrane.org/evidence/CD012034_using-de-escalation-prevent-violence-aggressive-people)). Vendor templates need scrutiny too: Intercom's guidance page labels "When a customer is angry, do not apologise. Instead, ask them to calm down politely" as a good example ([Intercom](https://www.intercom.com/help/en/articles/10560969-fin-guidance-best-practices-and-examples)).

The practical reading, an inference no study has directly tested, is to compress frameworks like HEARD and LAER into acknowledge-then-act: one specific acknowledgment of the situation ("a denial a few weeks before an appeal deadline is stressful"), then a concrete next step and timeframe, with apologies reserved for real service failures and given in explanatory form, which a preregistered IBM study found users generally preferred ([Ashktorab et al.](https://arxiv.org/abs/2507.02745)). Empathy may change wording but never a gate, a fact or a coverage answer. Detection should stay modest. Shipping contact-centre products expose polarity rather than discrete emotions; Zendesk calibrates its model so "a ticket isn't assigned a negative sentiment just because a customer has an issue," and Amazon Connect evaluates sentiment over trailing windows and defaults to neutral when data is missing ([Zendesk](https://support.zendesk.com/hc/en-us/articles/4550640560538); [AWS](https://docs.aws.amazon.com/connect/latest/adminguide/build-rules-for-contact-lens.html)). Claims conversations are full of inherently negative words (accident, death, denial), so the agent should separate a bad situation from anger at the service, and detect anxiety and confusion from behaviour such as repeated "what happens now?" questions rather than from sentiment scores. The channel matters legally: European Commission guidance, as summarised by law firms, places emotion inference from text outside the AI Act's biometric emotion-recognition rules, whereas voice analysis would be biometric and would trigger Article 50(3) disclosure ([CMS](https://cms.law/en/gbr/legal-updates/eu-commission-issues-guidelines-on-prohibited-ai-practices-part-ii); [EU AI Act Art. 50](https://artificialintelligenceact.eu/article/50/)).

### Refusing callers get one explanation, real alternatives and an exit

LLMs are persuasive enough that restraint becomes a compliance issue. GPT-4 given participants' sociodemographic data out-argued humans in 64.4% of non-tied debates ([Salvi et al.](https://ideas.repec.org/a/nat/nathum/v9y2025i8d10.1038_s41562-025-02194-6.html)); the EU AI Act prohibits manipulative techniques and the exploitation of vulnerabilities such as a specific social or economic situation ([Orrick](https://www.orrick.com/en/Insights/2025/04/EU-Commission-Publishes-Guidelines-on-the-Prohibited-AI-Practices-under-the-AI-Act)); and the Digital Services Act singles out "repeatedly requesting that the recipient of the service make a choice where that choice has already been made" as a practice its ban on manipulative interfaces can cover ([DSA Art. 25](https://www.springlex.eu/en/packages/dsa/dsa-regulation/article-25/)), a signal even where the DSA itself does not reach an insurer's own chat. The evidence on explaining a gate is thin but consistent. Fourteen percent of shoppers would abandon checkout if a phone number were simply required, and users mainly needed to know why ([Baymard](https://baymard.com/blog/explain-phone-number-field)); heavier justifications lowered trust and disclosure in a UC Irvine study ([Knijnenburg & Kobsa](https://isr.uci.edu/node/425.html)); and the popular "but you are free to refuse" compliance technique showed no effect in the seven low-risk-of-bias studies of a 52-experiment meta-analysis ([Fillon et al.](https://open.lnu.se/index.php/metapsychology/article/view/2640)). The pattern that follows is to state what is needed, give one sentence of why framed as protecting the caller's own claim and payout, offer alternatives (a different identifier, a one-time code, a phone channel), say what the agent can still do without verification, answer one follow-up question, and then stop with a human or channel offer, never a bypass and never a re-ask later in the session.

### Escalation is a designed outcome, not a failure state

Escalation defaults have converged. Fin hands off when a customer "clearly asks to speak to a human," on "strong frustration or anger," and when the customer is "stuck in a repetitive loop," with sample guidance to escalate on replies such as "That didn't help" ([Intercom](https://www.intercom.com/help/en/articles/12396892-manage-fin-ai-agent-s-escalation-guidance-and-rules)). Copilot Studio escalates "after two prompts" fail to resolve intent ([Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-copilot-studio/authoring-system-fallback-topic)), and Google's conversation design ends after two no-match attempts and warns against repeating a prompt verbatim "since it will sound robotic" ([Google](https://developers.google.com/assistant/conversation-design/errors)). The demand side explains why. In a 2026 vendor-sponsored survey, **trust in AI was 55% when a human escalation option was visible versus 26% without one**, and while 96% of leaders said they preserve context at hand-off, 83% of consumers said they repeat themselves after transfer ([CMSWire](https://www.cmswire.com/customer-experience/customers-the-ai-handoff-is-broken-contact-center-leaders-wont-hear-it/)). Gartner found 64% of customers would prefer companies not use AI for service, with difficulty reaching a person the top concern at 60% ([Gartner](https://www.gartner.com/en/newsroom/press-releases/2024-07-09-gartner-survey-finds-64-percent-of-customers-would-prefer-that-companies-didnt-use-ai-for-customer-service)), and the CFPB has documented chatbot "doom loops" with no way out ([CFPB](https://www.consumerfinance.gov/data-research/research-reports/chatbots-in-consumer-finance/chatbots-in-consumer-finance/)).

Over-escalation has costs too. Fin's support VP warns that broad guidance makes "escalations spike and resolution rate to drop," and that without office-hours configuration "the customer might get a flat refusal from the Agent with nowhere to go, which is worse than no guidance at all" ([fin.ai](https://fin.ai/blog/blueprint/how-to-set-your-escalation-policy)). Zendesk's AI agents check agent availability before offering a hand-off ([Zendesk](https://support.zendesk.com/hc/en-us/articles/8357749686554-Checking-operating-hours-and-agent-availability-during-conversations-with-AI-agents)), the UK FCA has highlighted firms that route bereavement chats straight to people ([FCA](https://www.fca.org.uk/cy/node/145621)), and Anthropic's car-insurance example targets at least 95% escalation accuracy, which forces measurement of both missed and unnecessary hand-offs ([Claude docs](https://platform.claude.com/docs/en/about-claude/use-case-guides/customer-support-chat)). Off-topic handling follows the same logic: a brief decline, a one-line scope statement, two or three things the agent can do, varied wording on repeats, and a human offer after about two misses ([Claude docs](https://platform.claude.com/docs/en/about-claude/use-case-guides/customer-support-chat); [Intercom](https://www.intercom.com/help/en/articles/10560969-fin-guidance-best-practices-and-examples); [Google](https://developers.google.com/assistant/conversation-design/errors)). Because topic classifiers can be beaten by bundling a related and an unrelated question, the agent should answer only the in-scope part with tools and decline the rest ([Beurer-Kellner et al.](https://arxiv.org/abs/2506.08837)). Because a confused claimant may phrase a real claim question oddly, it should ask one clarifying question before treating a turn as out of scope, following Google's advice to "assume the user is being cooperative" ([Google](https://developers.google.com/assistant/conversation-design/errors)).

### The follow-up email is a disclosure event

Customer-facing AI summary emails are not a mainstream vendor feature; Zendesk and Intercom offer transcripts instead ([Zendesk](https://support.zendesk.com/hc/en-us/articles/4408833687450); [Intercom community](https://community.intercom.com/messenger-8/do-users-always-receive-an-email-transcript-of-the-intercom-conversation-1124)), so the closest evidence is analogy. Apple paused AI news summaries after they produced false headlines ([ABC7](https://abc7news.com/post/apple-is-pulling-ai-generated-notifications-news-generating-fake-headlines/15810860/)), and Otter.ai emailed every meeting invitee a transcript that included private conversation recorded after the call ended ([UC Today](https://www.uctoday.com/security-compliance-risk/otter-ai-lawsuit-meeting-bot-recording-after-call/)). The law is manageable if the message stays purely transactional. CAN-SPAM treats a mixed message as commercial when its transactional content "does not appear mainly at the beginning of the message," with penalties up to $53,088 per email ([FTC](https://www.ftc.gov/business-guidance/resources/can-spam-act-compliance-guide-business)); for health claims, HHS allows unencrypted email of PHI only after a brief warning about interception risk and confirmation that the individual still wants it ([HHS](https://www.hhs.gov/hipaa/for-professionals/faq/2060/do-individuals-have-the-right-under-hipaa-to-have/index.html)); and an SMS version would bring TCPA consent and revocation rules ([Kelley Drye](https://www.kelleydrye.com/viewpoints/blogs/ad-law-access/fcc-sets-effective-date-for-tcpa-reasonable-consent-revocation-rules)). The value is real: J.D. Power found insurers deliver adequate digital claim updates only 22% of the time despite their weight in satisfaction ([J.D. Power](https://www.jdpower.com/business/press-releases/2025-us-claims-digital-experience-study/)), and Allstate already sends roughly 50,000 GPT-drafted claimant communications a day, with reps reviewing them for accuracy ([The Register](https://www.theregister.com/2025/02/13/allstate_insurance_ai_rep/)). The inferred design builds the summary from the structured event log rather than the transcript, copies status from the system of record, offers it once with a default of no, sends only to the address already on file, and excludes identifiers, full claim numbers and medical detail.

## Identity and consent law sets a higher bar than any three of five

No US statute fixes how many identifiers a caller must supply. HIPAA requires covered entities to "verify the identity of a person requesting protected health information and the authority of any such person" without prescribing a method ([45 CFR 164.514](https://www.law.cornell.edu/cfr/text/45/164.514)), and GLBA privacy duties for insurers are enforced through state insurance law ([15 U.S.C. 6805](https://www.law.cornell.edu/uscode/text/15/6805)). Published operating protocols are nonetheless stricter than the specification in one important respect: they require fixed sets of elements that must all match. The IRS tells assistors "Do not confirm or deny any taxpayer information until authentication has been successfully completed" ([IRS IRM 21.1.3](https://www.irs.gov/irm/part21/irm_21-001-003)), and a Medicare contractor's provider line requires all seven listed elements, including the beneficiary's date of birth and up to six letters of the surname "(ignore any spaces)," which doubles as a documented normalization rule ([CGS Medicare](https://www.cgsmedicare.com/jc/pubs/news/2024/02/cope150389.html)). Under an any-3-of-5 rule over name, date of birth, phone, email and ID last-4, a caller holding only name, phone and email, the least secret of the five, passes without a date of birth or ID digits.

Knowledge-based checks are weak even when stricter. NIST's final SP 800-63A-4, binding on US federal agencies, says **"Knowledge-based verification (KBV) or knowledge-based authentication SHALL NOT be used for identity verification,"** permitting it only as a fraud-management signal ([NIST](https://pages.nist.gov/800-63-4/sp800-63a.html)). A 2022 vendor case study found fraudsters passed contact-centre KBA 92% of the time against 46% for genuine customers, and noted that data dealers sell organized stolen personal data ([BusinessWire](https://www.businesswire.com/news/home/20220420005041/en)); researchers have shown SSNs can be predicted from date and place of birth ([Acquisti & Gross](https://www.heinz.cmu.edu/~acquisti/papers/AcquistiGross-PNAS-2009.pdf)). New York's DFS told regulated entities, insurers included, that MFA would be required for all authorized users "including customers" from November 2025 (whether a chat session counts as such access is a question for counsel), and urged avoiding SMS, voice or video authentication because of deepfakes ([NYDFS](https://www.dfs.ny.gov/industry-guidance/industry-letters/il20241016-cyber-risks-ai-and-strategies-combat-related-risks)). The largest deployed account assistants avoid in-chat KBA entirely: Bank of America's Erica works only inside the authenticated mobile app ([Bank of America](https://info.bankofamerica.com/en/digital-banking/erica.html)), and UnitedHealthcare's Avery and Elevance's assistant run inside member apps and portals ([UnitedHealth Group](https://www.unitedhealthgroup.com/newsroom/2026/2026-03-26-uhc-introduces-ai-companion-empowering-people-with-simpler-navigation-personal-experience.html); [Elevance Health](https://www.elevancehealth.com/newsroom/elevance-health-expands-virtual-assistant-to-help-members-navigate-healthcare-with-confidence)). Where KBA remains, OWASP's guidance applies: one generic failure message, failure counts per account rather than per IP, and a recovery path so that lockout cannot be weaponized ([OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)). Echoing identifiers is its own leak, since Amazon Lex warns that slot values used in prompts or responses "are not obfuscated in conversation logs" ([AWS](https://docs.aws.amazon.com/lexv2/latest/dg/monitoring-obfuscate.html)). The starter fixtures make the matching problem concrete: two policyholders' phone numbers differ only in the final digit, and one record stores "Yaven Li" as an alias for "Ya Wen Li," which argues for exact, normalized comparison in code, aliases drawn only from the record, and a near-miss counted as a miss.

The existence of the relationship is itself protected. The FTC privacy rule and NAIC Model 672 both define protected financial information to include the fact that an individual "is or has been one of your customers" ([16 CFR 313.3](https://www.law.cornell.edu/cfr/text/16/313.3); [NAIC Model 672](https://content.naic.org/sites/default/files/model-law-672.pdf)), and HHS says identifying information becomes PHI when "listed with health condition, health care provision or payment data" ([HHS](https://www.hhs.gov/hipaa/for-professionals/special-topics/de-identification/index.html)). Pre-verification replies therefore have to be identical whether or not a matching policyholder or claim exists.

Representative access has three legal footings, and the specification's son-with-consent case sits on the narrowest. A person with legal authority, such as a health-care power of attorney, is a personal representative whom a covered entity "must... treat... as the individual," subject to an exception where the entity suspects abuse or endangerment ([45 CFR 164.502](https://www.law.cornell.edu/cfr/text/45/164.502)). A family member involved in payment may receive only information "directly relevant to such person's involvement," and only with the individual's agreement, an opportunity to object, or a reasonable professional inference ([45 CFR 164.510](https://www.law.cornell.edu/cfr/text/45/164.510)). HHS's own example nearly matches the specification: a plan may disclose relevant PHI to "a beneficiary's daughter who has called to assist her hospitalized, elderly mother in resolving a claims or other payment issue," or to an HR representative "with the beneficiary also on the line" who can confirm the arrangement ([HHS FAQ 1067](https://www.hhs.gov/hipaa/for-professionals/faq/1067/may-a-health-plan-disclose-information-to-a-person-who-calls/index.html)). The minimum-necessary standard applies to the son but not to disclosures to the policyholder herself ([45 CFR 164.502](https://www.law.cornell.edu/cfr/text/45/164.502)). Outside HIPAA, Model 672 requires authorization before disclosing nonpublic personal health information except for listed insurance functions such as claims administration, and a valid authorization must be written or electronic, last no more than **24 months**, be revocable, and be kept in the record ([NAIC Model 672](https://content.naic.org/sites/default/files/model-law-672.pdf)). Operating practice bounds the options: the IRS's oral disclosure consent covers only the current conversation ([IRS IRM 21.1.3](https://www.irs.gov/irm/part21/irm_21-001-003)), 1-800-MEDICARE requires written permission ([CMS-10106](https://www.cms.gov/cms10106-authorization-disclose-personal-health-information)), and Kaiser requires a durable power of attorney or guardianship before a proxy can see the records of an adult who lacks capacity ([Kaiser Permanente](https://healthy.kaiserpermanente.org/northern-california/support/act-for-a-family-member)). A bot cannot exercise the professional judgment HIPAA allows when the patient is absent, and a chat cannot prove two people are present, so the defensible design, an inference, is an out-of-band consent request to the policyholder's on-file contact, scoped to this conversation by default, falling back to general information on timeout. The starter's pending-then-approved and timeout consent scenarios already have that shape.

PII controls are layered because each layer leaks. Microsoft's Presidio warns that "there is no guarantee that Presidio will find all sensitive information" ([Presidio](https://presidio.dataprivacystack.org/)); Dialogflow applies no redaction unless security settings are configured and keeps conversation history 365 days by default ([Google Cloud](https://docs.cloud.google.com/dialogflow/cx/docs/concept/security-settings)); and NYDFS expects disposal of NPI no longer needed, explicitly including NPI used for AI ([NYDFS](https://www.dfs.ny.gov/industry-guidance/industry-letters/il20241016-cyber-risks-ai-and-strategies-combat-related-risks)). California bars requiring SSN transmission over insecure connections and printing SSNs on mailed materials ([Cal. Civ. Code 1798.85](https://leginfo.legislature.ca.gov/faces/codes_displaySection.xhtml?lawCode=CIV&sectionNum=1798.85)). Retention pulls the other way: Virginia requires claim files detailed enough "to permit reconstruction of the insurer's activities," kept for the current year and at least the three preceding calendar years ([14VAC5-400](https://law.lis.virginia.gov/admincodeexpand/title14/agency5/chapter400/)), and HIPAA requires six-year retention of required documentation ([45 CFR 164.530](https://www.law.cornell.edu/cfr/text/45/164.530)). For health-plan claims, an LLM provider handling ePHI is a business associate needing a BAA "even if the CSP processes or stores only encrypted ePHI" ([HHS](https://www.hhs.gov/hipaa/for-professionals/special-topics/health-information-technology/cloud-computing/index.html)), and BAAs cover only listed features: Anthropic's covers prompt caching and structured outputs but excludes the Batch and Files APIs, and its covered models require 30-day retention unless zero data retention is expressly authorized ([Anthropic](https://privacy.claude.com/en/articles/8114513-business-associate-agreements-baa-for-commercial-customers)). Tracing must match; OpenAI's Agents SDK exposes `trace_include_sensitive_data=False` to keep model inputs, outputs and tool parameters out of traces ([OpenAI](https://openai.github.io/openai-agents-python/tracing/)).

AI disclosure is cheap to satisfy everywhere at once. EU AI Act Article 50(1), applicable from August 2, 2026, requires informing people they are interacting with an AI "at the latest at the time of the first interaction" ([EU AI Act](https://artificialintelligenceact.eu/article/50/)), and law-firm summaries of the May 2026 omnibus deal report that this duty was not deferred ([White & Case](https://www.whitecase.com/insight-alert/eu-agrees-digital-omnibus-deal-simplify-ai-rules)). US rules are narrower: California's bot law targets deception aimed at a sale or a vote ([Cal. BPC 17941](https://leginfo.legislature.ca.gov/faces/codes_displaySection.xhtml?lawCode=BPC&sectionNum=17941)), Maine requires clear notice whenever a reasonable consumer could think they are talking to a human ([Maine](https://legislature.maine.gov/statutes/10/title10sec1500-DD.html)), Utah requires disclosure on request and up front in high-risk interactions by regulated occupations ([Perkins Coie](https://perkinscoie.com/insights/update/new-utah-ai-laws-change-disclosure-requirements-and-identity-protections-target)), and Colorado's SB 26-189 dropped its blanket AI-interaction disclosure ([JD Supra](https://www.jdsupra.com/legalnews/colorado-ai-law-in-flux-comprehensive-2107294/)). The NAIC AI Model Bulletin, adopted by **25 states plus DC as of August 31, 2026**, expects insurers to give "notice to impacted consumers that AI Systems are in use" and to hold third-party AI to the insurer's own legal standards ([NAIC](https://content.naic.org/sites/default/files/legal-adoption-map-ai-model-bulletin.pdf); [Wisconsin OCI](https://oci.wi.gov/Pages/Regulation/Bulletin20250318AI.aspx)). An "I'm an automated assistant" line in the first message, truthful answers when asked, and a standing human offer satisfy all of them.

## Temperature zero is not determinism, so release on pass^k

Run-to-run variance is a property of the serving stack, not only of sampling. Thinking Machines generated 1,000 completions of one prompt at temperature 0 and got **80 unique completions**, because batch size varies with server load and changes kernel numerics ([Thinking Machines](https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/)). That is why τ-bench's pass^k metric, the probability that all k independent trials succeed, matters more than single-run accuracy, and Anthropic's evaluation guide spells out the arithmetic: a 75% per-trial success rate passes three trials in a row only "(0.75)³ ≈ 42%" of the time ([Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)). MyCity's one-correct-then-ten-wrong voucher answers are exactly what a single-run QA process misses.

Benchmarks also show where agents break. τ²-bench found that letting the simulated user hold some of the tools cost 18 to 25 points, and that success approaches zero for tasks needing more than seven actions ([Barres et al.](https://arxiv.org/abs/2506.07982)). Sierra's τ³ release found the best model solved about 25% of tasks over large, messy policy corpora and "just 40%" even when handed the exact documents, while voice agents scored 26–38% with realistic audio, where Sierra found that **"Authentication is the bottleneck"** ([Sierra](https://sierra.ai/blog/bench-advancing-agent-benchmarking-to-knowledge-and-voice)). That argues for keeping this agent's knowledge surface small (structured claim fields plus short vetted document guidance rather than long-document retrieval) and, if it runs on voice as the specification's "caller" language and the starter's audio-demo notes suggest, for treating identity capture as the weakest step. The benchmarks have validity problems of their own: τ²'s user simulators erred in 16–47% of conversations ([Barres et al.](https://arxiv.org/abs/2506.07982)), Princeton's HAL scores only a 26-of-50-task "clean" airline subset ([HAL](https://hal.cs.princeton.edu/reliability/benchmark/taubench_airline)), Amazon's τ²-bench-Verified corrects tasks whose expected actions contradict the policy ([amazon-agi](https://github.com/amazon-agi/tau2-bench-verified)), and vendor results can include prompt addenda instructing the model "to better target its known failure modes" ([Anthropic](https://www.anthropic.com/news/claude-sonnet-4-5)). Capable models also find letter-of-policy loopholes: Claude Opus 4.5 upgraded a basic-economy cabin first so it could then modify a booking the policy said could not be modified, a move Anthropic judged legitimate in that task but flagged as the kind of "clever paths around intended constraints" that could be reward hacking elsewhere ([Anthropic](https://www.anthropic.com/news/claude-opus-4-5)), and Salesforce's CRMArena-Pro found agents show "near-zero inherent confidentiality awareness" ([CRMArena-Pro](https://arxiv.org/abs/2505.18878)). Both findings argue for enforcing "no claim details before verification" in the tool layer and testing for leakage explicitly.

Mature teams test conversational agents the way they test code. Sierra generates simulated conversations from SOPs, knowledge bases and past transcripts, varies personas by language, tech comfort and tone, has "an independent judge" check goal completion, SOP adherence, brand and accuracy, and lets customers "gate releases on specific simulations — just like unit tests," reporting over 35,000 tests a day across customers ([Sierra](https://sierra.ai/blog/simulations-the-secret-behind-every-great-agent)). Decagon pairs unit tests for "on-brand, policy-aligned responses" and integration tests that agents "trigger the right tools" with simulations that inject anger, stress and frustration ([Decagon](https://decagon.ai/blog/the-future-of-ai-agents-is-test-driven); [Decagon](https://decagon.ai/blog/decagon-simulations)). Rasa's end-to-end tests assert `slot_was_set`, `slot_was_not_set`, `flow_started` and `generative_response_is_grounded` with custom actions stubbed out ([Rasa](https://rasa.com/docs/pro/testing/evaluating-assistant/)), and Pydantic AI's `TestModel`, `FunctionModel` and `ALLOW_MODEL_REQUESTS=False` let orchestration logic run without a live model ([Pydantic AI](https://pydantic.dev/docs/ai/guides/testing/)). Anthropic's guidance orders the graders: code-based checks for state and tool calls first, calibrated model graders for nuance, humans as the gold standard, and "grade what the agent produced, not the path it took" ([Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)). For this agent that implies two layers. Deterministic replays of recorded extractor outputs prove the gates, counters and rendering with zero-tolerance assertions, such as no claim field in any reply before verification. Live-model persona simulations (anxious, angry, confused, refusing, adversarial, a son without consent, injected instructions inside a denial reason) run at least four to eight times each, are reported as pass^k, and are reviewed by humans, because simulators and judges also err.

## Conclusion

The deepest lesson from these systems is that an SOP should be compiled, not prompted. The SOP text becomes two artifacts: a state machine that owns gates, order, counters and consent, and per-step language guidance that owns tone and explanation. The test for which artifact a rule belongs in is whether breaking it would be a legal or security event; if so, the model must be unable to break it, because written policy barely moved agent behaviour on τ-bench and published classifier-style defences keep falling to adaptive attacks. The less obvious finding is that determinism is a user-experience feature as much as a compliance one. The failures that pushed vendors back to hybrids were re-asked questions, loops and forgotten context, exactly what makes an anxious claimant feel unheard, and for a disclosed AI the empathy research says specific, competent action earns more goodwill than emotional language.

The hard problems for this agent are therefore not conversational fluency, which current models handle well, but three things the specification treats as settled: identity assurance when the only in-chat tool, a knowledge-based check, is one NIST rejects for identity verification, representative consent where the medium cannot prove who is present, and consistency across thousands of runs. The evidence base is lopsided toward vendor documentation, no insurer has published a claims-chatbot postmortem, and none of the thresholds that matter most (verification attempts, escalation counts, sentiment persistence) has public outcome data. A team that instruments this agent carefully will be generating evidence the industry has not yet published.

## Prioritized build list for the claims agent

Priorities run from P0 (security, privacy or legal exposure; required before any real caller) through P1 (correctness and experience; required before launch) to P2 (operational hardening). The first table holds decisions with direct support from documented practice, law, benchmarks or incidents. The second holds this report's inferences: reasoned from the evidence but untested, each with a way to validate it. The third lists pitfalls alongside the incident that demonstrates each.
